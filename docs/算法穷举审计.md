# 算法穷举审计报告

> 2026-10-23 · 覆盖 `bsp/ main/ menu/ page/ ctrl/` 中 14 组纯算法
> 脚本：`build_tools/algo_audit.py`（可复跑）；原始输出：`docs/algo_audit.txt`
> 首轮 60 PASS / 3 FAIL → 修复 2 个缺陷后 **63 PASS / 0 FAIL**

## 方法

每个算法按 C 源码**逐行移植**成 Python，显式建模 C 的整数语义：

- 除法**向零截断**（Python `//` 是向下取整，负数会差 1，故用 `cdiv()`）
- 算术右移等价向下取整（Python `>>` 天然一致）
- 只在源码确实发生的地方模拟 int16 截断/饱和

判据分三类：**PASS**（不变量成立）、**FAIL**（缺陷）、**NOTE**（已知取舍或设计分工）。

**结果：60 PASS / 3 FAIL / 9 NOTE**（3 个 FAIL 归并为 2 个缺陷）。

## 缺陷 1（已修复）：样条在斜率变号处产生负切线 → 校准偏移曲线过冲

**位置**：`main/work_task.c` `spline_interp()` 的节点切线钳位

```c
t[k] = (m[k - 1] * dx_r + m[k] * dx_l) / (dx_l + dx_r);
if (t[k] < 0) t[k] = 0;
mlo = (m[k - 1] < m[k]) ? m[k - 1] : m[k];
if (t[k] > 3 * mlo) t[k] = 3 * mlo;   /* 保证段内单调 */
```

相邻两段斜率**异号**时 `mlo` 为负，`3*mlo` 也是负数，于是刚被钳到 `≥0` 的切线**又被钳成负值**——方向与段内走向相反，段内必然过冲。

**为什么只在 `cal_offset_interp` 触发**：`adc_to_temp` 的样条输入是 ADC 升序 + 温度升序，所有 `m > 0`，走不到这条分支。而校准偏移量可正可负、可不单调，几乎必然出现斜率变号。

**修复前实测越界**：

| 偏移曲线 | 段内最大越界 | 符号错误的切线 |
|---|---|---|
| `[-3, 2, -1, 1, -2]` | **2 °C** | 3/3 |
| `[-6, 5, -2, 3, -4]` | **4 °C** | 3/3 |
| `[10, -5, 3, 0, -2]` | **1 °C** | 2/3 |
| `[-8, 6, -4, 5, -3]` | **6 °C** | 3/3 |
| `[0, 4, -6, 2, -1]` | **8 °C** | 3/3 |
| `[12, -12, 8, -8, 4]` | **5 °C** | 3/3 |

**修复后**：6 组曲线全部 **0 越界 / 0 错误切线**，节点导数跳变从 1 单位/°C 降到 **0**。

**修法**（Fritsch-Carlson 标准写法，支持递增/递减/变号）：

```c
/* 节点是局部极值(两侧斜率异号): 切线必须水平, 否则段内会冲过端点 */
if ((m[k - 1] > 0) != (m[k] > 0))
{
    t[k] = 0;
    continue;
}

t[k] = (m[k - 1] * dx_r + m[k] * dx_l) / (dx_l + dx_r);

/* |t| <= 3*min(|m[k-1]|, |m[k]|), 符号保持不变 */
a3 = 3 * ((m[k - 1] < 0) ? -m[k - 1] : m[k - 1]);
b3 = 3 * ((m[k] < 0) ? -m[k] : m[k]);
lim3 = (b3 < a3) ? b3 : a3;
if (t[k] > lim3)       t[k] = lim3;
else if (t[k] < -lim3) t[k] = -lim3;
```

**等价性要说准确**（首版报告这里写错了，2026-10-24 修正）：

- **温度插值那一段完全等价**：`adc_to_temp` 里 `spline(adc, {200,300,350,400,450})` 的两侧斜率全为正，新旧上界相同。实测偏移全 0 时 ADC 0..4095 **0 个差异**
- **偏移插值那一段故意改变**：`cal_offset_interp` 的 `ys` 是校准偏移量，可正可负，正是过冲的来源。修正后它不再过冲，所以 `adc_to_temp` 的输出会变

**对现有已校准设备的影响**（同一组校准点，升级前后读数差）：

| 偏移曲线 | 偏移插值最大变化 |
|---|---|
| `[-3, 2, -1, 1, -2]` | **3 °C** |
| `[5, -3, 2, -4, 1]` | **3 °C** |
| `[-5, 4, -3, 3, -2]` | **7 °C** |
| `[12, -12, 8, -8, 4]` | **10 °C** |

即：偏移量在 ±3 °C 量级的正常校准，读数会变化最多 3 °C；偏移越极端变化越大。这不是回归，是把原来的过冲去掉后的正确值，但**升级后用户可能觉得"温度变了"**，提交信息里要写明。

## 缺陷 2（已修复）：前馈底座学习系统性偏低 19%

**位置**：`main/work_task.c` `learn_ff_hold()`

滤波值直接写 `g_config`，而写回要跨过 `|Δk| ≥ 2` 的死区：

```c
k = g_config.pid_hold_k[h];              /* 每次从配置重读 */
if (k == 0) k = HOLD_K_SEED;
k = (uint16_t)(((int32_t)k * 7 + k_now) / 8);
if (|k - g_config.pid_hold_k[h]| >= 2)   /* 死区不满足就不写回 */
    g_config.pid_hold_k[h] = k;
```

死区一旦不满足，下一周期又从**旧值**重算，收敛条件退化成

```
|k_new − k| = |k_now − k|/8 < 2   ⟺   |k_now − k| < 16
```

进 ±15 死区就**永久停住**，再也靠近不了 `k_now`。

**修复前**（稳定后 400 周期）：

| 设定点 | 理想 k | 学到的 k | 残差 | 底座误差 |
|---|---|---|---|---|
| 200 | 91 | 77 | −14 | −24 |
| 250 | 84 | 69 | −15 | −33 |
| 350 | 80 | 66 | −14 | −45 |
| 450 | 75 | 61 | −14 | **−59（6.6% 满量程）** |

**修复后**：

| 设定点 | 理想 k | 学到的 k | 残差 | 底座误差 |
|---|---|---|---|---|
| 200 | 91 | 87 | −4 | −7 |
| 250 | 84 | 80 | −4 | −9 |
| 350 | 80 | 77 | −3 | −9 |
| 450 | 75 | 72 | −3 | **−12（1.3% 满量程）** |

**修法**：滤波中间值放 RAM，死区只控制**落盘**；滤波加半个除数四舍五入（否则 `|k_now−k| < 8` 时整除为 0 仍会停住）。

```c
static uint16_t hold_k_filt[HANDLE_NUM];   /* 6 字节 RAM */

k = hold_k_filt[h];
if (k == 0)
{
    k = g_config.pid_hold_k[h];
    if (k == 0) k = HOLD_K_SEED;
}
k = (uint16_t)(((int32_t)k * 7 + k_now + 4) / 8);   /* +4 = 四舍五入 */
hold_k_filt[h] = k;                                  /* 每周期推进 */
if (|k - g_config.pid_hold_k[h]| >= HOLD_SAVE_DELTA_K)
{
    g_config.pid_hold_k[h] = k;
    hold_dirty = true;
}
```

剩余残差 ≤ 4 来自"1/8 滤波的整数分辨率 + 落盘死区各留 1"，被积分限幅（90 单位）完全覆盖。

## 已确认无误的部分（要点）

- **去极值平均**：新公式严格满足 `|6r−s| ≤ 3`；旧公式最大偏高 1.00 LSB，40.8% 的帧受影响（已修）
- **ADC→温度**：3 组校准下全量程**单调不减**，相邻 ADC 跳变 ≤ 2 °C，范围严格在 [0,600]
- **PID**：39600 组状态穷举，输出恒在 [0,900]、积分恒在 [−90,90]；闭环 250/350/450 °C 稳态误差 **0.0 °C**，过冲 ≤ 0.1 °C，稳定 12~20 s
- **编码器**：`residual` 恒在 ±3；同向位移严格守恒；2 万条随机游走偏差 ≤ 2.5 计数/次换向（固有半格损失）
- **队列**：32×32 穷举，空/满判据互斥且与 `used` 一致；旋转上限 28、按键上限 31、预留槽 3
- **菜单窗口**：count 1..20 全枚举，**当前项恒占且仅占一行**，`win_top+win_cursor` 恒等于当前下标（这条不变量正是"列表卡住/错位"的防线）
- **型号识别**：分区随电流单调不降；T12 未标定时两个方向的粗门限都不误伤
- **CRC16**：标准向量 0x4B37；320 个单比特 + 74 个突发错误全部检出
- **配置钳位**：全部收敛且幂等（不会每次上电白擦 Flash）
- **自整定**：成功时严格满足 Z-N 关系、失败时增益全 0（不留半套参数）；`tune_gain_sat` 保证增益恒在 [0,32767]

## 已知取舍（NOTE，不算缺陷）

| 项 | 量化 |
|---|---|
| 去极值平均只能抑制 1 帧毛刺 | 2 帧同向毛刺（5×1000+0+0+2000）偏差 −167 LSB |
| 前馈斜坡在 −10 °C 处不从 0 起步 | 阶跃 85 单位 = 9.4% 满量程 |
| 200 °C 接缝斜率突变 | 低温段斜率是 200~450 段的 2.8~4.0 倍 |
| 校准失效分支上限仅 120 °C | 但 `Cal_Init` 保证校准有效，实际不可达 |
| 编码器换向反射 | 每次换向最多丢 2 计数（半格），算法固有 |
| 自整定幅值门限 30 °C | 摆动 <30 °C 一律判"整定无效" |
| 自整定 Kd 超页面上限 | 12 组成功样本中 11 组 Kd > 1000，最大 17042 被削到 **6%** |
| Tu 量化 | `half_len_sum/8*2`，步长 0.4 s；大周期小幅值时高估约 6% |
| 低通量化死区 | 温度终值差 1 LSB；CPU 补偿滤波停在 854/1000 |
| 休眠/关机冲突 | 7381 组中有 1891 组 `shutdown ≤ sleep`，由设置页诊断而非 clamp 处理 |
