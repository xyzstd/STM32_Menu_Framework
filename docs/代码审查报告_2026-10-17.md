## 2. 高优先级

### H1. 两个含中文的源文件丢了 UTF-8 BOM ✅ 已修复
`bsp/key.h`、`menu/menu.h`

`fix_bom.py` 报告 `含非 ASCII 但缺 BOM: 2`。两个文件都含中文注释。本工程约定中文源码必须带 BOM（AC5 在无 BOM 时可能按本地代码页解析，注释末字节与后续字符组合有把注释吞掉/报错的风险）。这是本次编辑时被工具写回丢掉的（`Write`/脚本重写不会保留 BOM）。

修法：`python build_tools/fix_bom.py --fix`，然后重编译确认。

### H2. 按键去抖从 20 ms 缩短到 15 ms，尚未见真机验证记录
`bsp/key.h:11` — `KEY_DELAY_TIME 4 → 3`（每 5 ms 扫描一次，即 20 ms → 15 ms）

手感会更跟手，但机械按键的抖动窗口典型在 5~20 ms，15 ms 处在边界上。风险是偶发"按一次算两次"（在 HOME 上表现为温度跳 10°C，在确认页表现为误选）。建议：真机连续快速点按 100 次做一次计数验证；若出现重复触发，退回 4。这条不是代码错误，是**行为变更需要实测背书**。

### H3. 换型号落盘失败时不回滚 `handle_type` ✅ 已修复
`page/handle.c:86-92`

```c
g_config.handle_type = cur_idx;
saved = Config_Save();
WorkTask_OnHandleChanged();     /* 已按新类型重载 PID */
if (saved) Toast_Saved(); else Buzzer_Beep(ALARM);
```

Flash 写失败只蜂鸣，**RAM 里的型号仍是新的**：本次运行按新型号的温度曲线和 PID 增益工作，重启后又变回旧型号。用户听到一声蜂鸣、看到"切换完成"，实际处于"运行态与持久态不一致"的状态。自整定路径（`work_task.c:890-901`）对同类失败是回滚 + 重写的，这里口径不一致。

建议：失败时 `g_config.handle_type = 旧值; WorkTask_OnHandleChanged();` 再告警，或明确提示"切换仅本次有效"。

### H4. 温度校准落盘失败完全静默 ✅ 已修复
`page/calibrate.c:217`

```c
(void)Cal_Save();   /* 注释：返回值暂不向用户上报 */
```

校准偏移直接叠加到读温上（`cal_offset_interp` → `spline_interp`），是**影响控温准确性**的数据。写失败时用户退出页面、看到新偏移已生效（RAM 已改），重启后全部丢失且无任何提示。其它页面（param/pid/settings/handle/cur_cal）都已统一为"成功弹框、失败蜂鸣"，这里是唯一的例外。

建议：改为 `if (!Cal_Save()) Buzzer_Beep(BUZZER_EVENT_ALARM);`，与其它页对齐。

## 3. 中优先级

### M1. 菜单表运行期校验被移除，防线只剩一个手动脚本 ✅ 已加固
`menu/menu.c`（无 `menu_validate_table`）、`menu/menu.h`（无 `Menu_IsValid`）

内核现在对表结构**完全信任**：`menu_child_end()` 只做局部越界判定，索引 0 是否为虚拟根、HOME 是否在 1、parent/child 是否自洽，全靠 `build_tools/check_menu_table.py`。但该脚本**不在编译流程里自动执行**——改表后忘记跑，构建照样 0 Error，问题要到上机按键异常才暴露。

建议（不改内核）：把 `check_menu_table.py` 挂进构建前步骤，或提供 `build_tools/prebuild.py` 一次性跑全部检查（menu 表 / 汉字 / ASCII / ROM / BOM）。

### M2. `MENU_RET_DONE` 分支用的是"旧节点"指针
`menu/menu.c:135-141`

```c
if (ret == MENU_RET_DONE) {
    menu_exit_handler();          /* 可能回调 exit，exit 里若跳页会改 current */
    if (item->child_num > 0)      /* item 是跳页前的节点 */
        menu_enter();             /* 但操作的是跳页后的 current */
}
```

当前工程所有 `exit` 回调都不跳页（已逐一核查：`cur_cal_exit`、`handle_exit`、`calibrate_exit`、`sleep_set_exit`、`func_set_exit`、`param_exit` 均只做落盘/断热/标志复位），所以是**潜在**问题而非现网缺陷。但这条约束没有任何强制手段，将来谁在 exit 里加一次 `Menu_SetCurrentId` 就会踩到。

建议：`menu_exit_handler()` 之后重取一次 `item = Menu_GetItem(menu_ctrl.current);` 并判空，或在头注释里把"exit 回调禁止跳页"写成硬约定。

### M3. `Heater_Enable()` 会重放上一次功率，存在 ≤200 ms 的陈旧输出窗口
`ctrl/heater.c:60-65`

`Heater_Disable()` 有意不清 `heater.power`，`Heater_Enable()` 会把它原样写回 PWM。工作层已在多数路径补了 `Heater_SetPower(0)` 再使能（自检、Recover、handle_exit），但两处没有：

- `work_task.c:1198-1199`（`WorkTask_MarkActivity` 唤醒）
- `work_task.c:1232-1233`（`SetCalSuppress(false)`）

代码注释已承认并论证"最长 200 ms、约 13 J，可接受"。这是有意识的取舍，记录在案：若将来把 PID 周期调长，这个窗口会同比放大。

### M4. `config_clamp()` 只收敛了休眠三项
`bsp/config.c:210-235`

函数头注释明确"目前只覆盖休眠三项；其余字段的收敛按需补充"。现状：

- `default_temp` 越界 → 被 `PID_Controller_SetSetpoint()` 的钳位兜住（不会越界控温），但 HOME 显示的初始目标可能与实际不符；
- `pid_agg_*` / `pid_cons_*` 越界 → 输出被 `Heater_SetPower` 钳到 900，不会烧，但控温质量可能异常且无提示；
- `brightness` 是 `uint8_t`，天然安全。

建议：至少把 `default_temp` 与六个 PID 增益一并纳入（范围常量已在 `config.h`，成本很低）。

### M5. 配置单副本、擦后写，掉电会丢全部设置
`bsp/config.c:175-185`（`save_page`）

擦除 → 编程，两步之间掉电则整页无效，下次上电 `magic` 不符回落出厂默认（校准页同理）。叠加 `remember_last_temp()`（`work_task.c:490-504`）在**每次入睡/关机**都落盘一次，擦写频次不低。

- 安全性：不构成风险（回落默认是安全侧）；
- 体验：偶发掉电会丢失全部用户设置（温度/PID/校准）。

若在意，可做双页 A/B（带序号 + CRC 选新），成本约 1 页 Flash 与 ~30 行代码。当前不是必须项。

### M6. `static inline` 在 AC5 下不生效
`menu/menu.c:81, 87`（`menu_ops_activatable`、`menu_child_end`）

本工程实测结论（已记录在项目记忆里）：armcc 把 `inline` 当纯提示，当前优化等级下不内联，两个函数仍各自生成独立代码。功能无影响，仅体积/调用开销。若确实想内联需写 `__forceinline`。

## 5. 做得扎实的部分

- **加热安全联锁完整**：热电偶短路/开路（双阈值 + 8 周期去抖）、过温锁存、过流（差分校准 + 新鲜度判定）、加热器无温升诊断（仅满功率 + 20 s 窗口）、IWDG ~2 s、上电四步链路自检、校准数据非法禁加热。每条都锁存而非仅断热，避免"静默永久停加热"。
- **电流采样设计**：导通/关断双相位由 CC4 锁定，差分消运放失调；`AD_GetCurrent` 的"读-清原子化"与新鲜度标志处理得很干净。
- **输入并发模型**：SPSC 无锁环形队列、head/tail 单向所有权、`Input_ClearEvents` 只推进 head（修掉了清零 tail 的交错缺陷）、旋转事件带时间戳做过期丢弃。
- **Flash 持久化**：三页分离（配置/校准/电流标定）、CRC 覆盖到 `offsetof(crc)`、数组连续性的编译期守卫、落盘失败回滚（自整定/PID 页）。
- **注释质量**：安全关键路径的注释写的是"为什么这么设计"（阈值依据、失败方向、历史缺陷），而不是复述代码——这是本项目最大的可维护性资产。
- **菜单内核**：`menu_child_end` 把"子区间计算 + 越界判定"收成一处，`menu_enter`/`Menu_GetSiblingRange`/`menu_validate_table` 共用；导航路径逐条做了边界判定，即使表配错也不会越界读写。

## 6. 建议处理顺序

1. **H1**（BOM）——一条命令，先做，避免后续编辑继续踩。
2. **H3 / H4**（落盘失败回滚与提示）——涉及数据可信度，改动小。
3. **M1**（把检查脚本挂进构建流程）——防止改表漏检，收益最大的一次性投入。
4. **H2**（去抖）——真机验证后再定是否保留。
5. **M2 / M4 / L1**——顺手收敛，避免将来踩坑。
6. M3 / M5 / M6 / L2 / L3 / L5 / L6——按需，不阻塞发版。
