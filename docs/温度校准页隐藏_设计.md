# 设计：温度校准页隐藏（版本页长按解锁）

> 状态：**已定稿，尚未实施**（2026-10-23）
> 目标读者：下一次动手实现的人（含未来的自己）
> 关联：`menu/menu_table.c`、`menu/menu_display.c`、`main/input.c`、`page/settings.c`

## 1. 需求

- 「温度校准」这一项**默认不出现在列表里**
- 在「系统设置 → 版本信息」页**长按**，页面出现感叹号 `!`，该项变为可见
- 断电后自动恢复隐藏（不写 Flash）

## 2. 方案选型（为什么不用另外两种）

| 方案 | 做法 | 否决理由 |
|---|---|---|
| A 表重排 + 长按直达 | 把校准页挪到区间末尾，`child_num` 静态 = 5，长按后 `Menu_SetCurrentId` 跳进去 | 长按在本项目是 `menu_back`（返回）语义，改成跳转破坏一致性；且用户明确要求"版本页只提供可见通道，不做导航" |
| B 表放 RAM | 去掉 `menu.h` 的 `const`，运行时切 `child_num` | 表从只读变可写，越界写可能悄悄改坏菜单结构；+240B RAM |
| **采用：隐藏标志 + 可见数** | 表保持 `const`，`flags` 声明"默认隐藏"，RAM 一个 bool 管解锁，读取侧过滤 | — |

**选它的核心理由**：只改**读取侧**（渲染 + 导航后处理），不动**数据侧**（表结构、可写性）。读取侧改动幂等、可回退、出错范围局部；数据侧改动会污染全局不变量。

## 3. 现状（实施前的事实基线）

菜单表 15 项，HOME=1，顶层子项 `[2..7]`：

| 索引 | 名称 | 类型 |
|---|---|---|
| 2 | 温度设置 | 叶子页 `temp_ops` |
| 3 | PID设置 | 容器，子项 `[12..14]` |
| **4** | **温度校准** | **叶子页 `calibrate_ops` ← 要隐藏** |
| 5 | 手柄型号 | 叶子页 `handle_ops` |
| 6 | 固件升级 | 叶子页 `ota_wait_ops` |
| 7 | 系统设置 | 容器，子项 `[8..11]` |

关键内核行为（已核对代码）：

- `Menu_GetSiblingRange()` 返回**原始连续区间** `[first_child, first_child+child_num)`，不扫描 `parent` 字段
- `menu_ctx()` 在 `MENU_STATE_NORMAL` 态取的是**当前项的 parent** → 同一列表内移动光标，指纹不变
- `menu_state_normal()` 里 `UP/DOWN` 只走一步；`CLICK` 进页；`LPRESS` 返回
- `Menu_SetCurrentId()` 末尾**无条件**调 `menu_enter_handler()` → 落到叶子项会直接打开页面（所以不能用它移光标）
- `Menu_EventDispatch()` 是公开 API，可重复调用
- `UI_RequestRefresh()` 只是置一个布尔量，渲染时消费；`UI_Task_Process` 有 2ms 合并窗口

## 4. 机制

### 4.1 标志与访问器（新文件 `menu/menu_table.h` / `.c`）

```c
#define MENU_FLAG_HIDDEN   0x02U   /* bit0 已被 MENU_FLAG_DIRECT_HANDLER 占用 */

static bool hidden_unlocked = false;   /* RAM; 上电 false = 隐藏 */

bool MenuTable_IsHidden(uint8_t id)
{
    const menu_item_t *it = Menu_GetItem(id);
    if (it == NULL || !(it->flags & MENU_FLAG_HIDDEN))
        return false;
    return !hidden_unlocked;
}

void MenuTable_UnlockHidden(void) { hidden_unlocked = true; }

/* [first, first+count) 内可见项数 */
uint8_t MenuTable_VisibleCount(uint8_t first, uint8_t count);

/* id 在列表内的"压缩下标"(前面有几个可见项); id 本身隐藏时返回可见数 */
uint8_t MenuTable_VisibleIndexOf(uint8_t id, uint8_t first);

/* 压缩下标 → 原始偏移(相对 first) */
uint8_t MenuTable_RawAt(uint8_t first, uint8_t vis_index);
```

要点：**表里只声明意图（默认隐藏），是否解锁放 RAM**。于是表永远 `const`，上电自动复位，不用写 Flash。

`menu_table.c` 里给 `[4]` 加 `.flags = MENU_FLAG_HIDDEN`。

### 4.2 渲染层（`menu/menu_display.c`）

`menu_list_display()` 里两处：

```c
uint8_t raw   = (uint8_t)(last - first + 1);
uint8_t vis   = MenuTable_VisibleCount(first, raw);
uint8_t index = MenuTable_VisibleIndexOf(selected, first);   /* 压缩下标 */

if (vis == 0u)                     /* 全隐藏: 兜底, 复用现成路径 */
{
    win_first = 0xFF;
    Menu_SetCurrentId(MENU_HOME_ID);
    return 20;
}

menu_list_advance(index, first, vis);
menu_list_render(first, vis, index);
```

`menu_list_render()` 里把"压缩下标 → 原始 id"补上：

```c
for (r = 0; r < lines; r++)
{
    uint8_t cidx = menu_row_index(r, count);      /* count 现在是可见数 */
    if (cidx >= count) break;

    uint8_t off = MenuTable_RawAt(first, cidx);
    uint8_t id  = (uint8_t)(first + off);
    const menu_item_t *item = Menu_GetItem(id);
    ...
    if (cidx == index) menu_reverse_row(y);       /* 反显判据也用压缩下标 */
}
```

`menu_row_index()` / `menu_list_advance()` / `menu_move_dir()` **一行都不用改** —— 它们拿到的 `count` 和 `index` 已经是压缩语义，自洽。

### 4.3 输入层（`main/input.c`）

```c
static bool input_dispatch(const input_evt_t *evt)
{
    menu_cmd_t cmd;
    uint16_t ctx_before = menu_ctx();

    cmd.event = (menu_event_t)evt->event;
    cmd.step  = evt->step;
    menu_notify(&cmd);                      /* 首次: 方向映射 + MarkActivity + 请求刷新 */

    /* 落点若是隐藏项, 同方向再走一步 —— 内核没有"设置光标"的接口, 只能"走了再看".
     * 依赖两个内核实现细节(无接口契约保护, 改 menu.c 时必须回来看):
     *   ① menu_ctx() 在 NORMAL 态用"当前项的 parent"做身份 → 同列表内移动不清队列;
     *   ② menu_move_up/down 只走一步, 不会自己跳过任何项. */
    if (Menu_GetState() == MENU_STATE_NORMAL &&
        (cmd.event == MENU_EVENT_UP || cmd.event == MENU_EVENT_DOWN))
    {
        uint8_t guard = 0;

        while (MenuTable_IsHidden(Menu_GetCurrentId()) && ++guard < 32u)
            Menu_EventDispatch(&cmd);       /* 直接调公开 API, 不再走 menu_notify */
    }

    return menu_ctx() != ctx_before;
}
```

为什么这样安全：

1. **不清队列**：同列表内 `parent` 不变 → `menu_ctx()` 相同 → `input_dispatch` 返回 false → 不触发 `Input_ResetForJump()`
2. **看不到中间帧**：渲染在 `Input_Process` 返回之后
3. **不重复刷新**：额外那次绕过 `menu_notify`，`WorkTask_MarkActivity` / `UI_RequestRefresh` 各只调一次
4. **不死循环**：`guard < 32`（表 15 项，留一倍余量）

`menu_notify` 的方向反转只在 NORMAL 态做一次，所以重发时直接用已映射过的 `cmd`，不会二次反转。

### 4.4 版本页（`page/settings.c`）

| 事件 | 行为 |
|---|---|
| `LPRESS` | `MenuTable_UnlockHidden()` + `UI_RequestRefresh()`，返回 **`MENU_RET_STAY`**（留在本页） |
| `CLICK` | 返回 `MENU_RET_DONE`（退出页，保持现状） |

- **必须留在本页**，否则页面立刻退出、感叹号一闪而过，"确认已解锁"的意义就没了
- **必须调 `UI_RequestRefresh()`**：`version_display` 返回 0 是纯事件驱动，不刷新不重绘
- `version_display` 里解锁后画 `!`（建议在版本号下方一行）
- 建议加一声 `Buzzer_Beep()`（`settings.c` 已在用）作为解锁反馈，比跳转克制
- **不做 toggle**（再次长按取消解锁）：上电复位已覆盖需求，加 toggle 反而让误触变成困惑

## 5. 边界与兜底

| 情况 | 处理 |
|---|---|
| 列表内全部项隐藏 | `vis == 0` → 回落 HOME（4.2 的兜底分支） |
| 连续两个隐藏 | 循环走两次，`guard` 计数 |
| 隐藏项在末尾 + 环绕 | `menu_move_up/down` 的 `current=first/last` 自然环绕，多走一步正好落到首/末可见项 |
| 解锁瞬间列表项数 5→6 | `menu_list_advance` 里 `count != win_count` **自动复位窗口**，不会错位 |
| 隐藏项被 `Menu_SetCurrentId` 直达 | **拦不住**，这是 UI 隐藏而非访问控制（见 §8） |

## 8. 两个必须写进代码注释的提醒

1. **`Menu_GetSiblingRange()` 返回的是原始区间（含隐藏项）**。将来若有人拿它算"列表有几项"，必须改用 `MenuTable_VisibleCount`。
2. **这是 UI 隐藏，不是访问控制**。`Menu_SetCurrentId()` 仍能直达隐藏项 —— `page/cur_cal.c` 就是靠它跳 `CUR_CAL_CAL_MENU_ID=14` 的。若哪天 `CUR_CAL_MENU_ID` 被配错指向 4，照样能进校准页。真正的权限要在 `calibrate_ops.enter` 里检查标志。

## 9. 建议给校验脚本加的两条规则

`build_tools/check_menu_table.py` 是菜单表的唯一防线（内核里没有运行期校验）。新增：

1. `MENU_FLAG_HIDDEN` **只能标在叶子项上**（容器隐藏会让其子项变孤岛，`parent` 链校验也会报错）
2. **同一列表至少保留一项可见**（否则 `vis == 0`，虽然渲染层有兜底，但那意味着这张表配错了）

## 10. 验证计划（实施后）

1. `python build_tools/prebuild.py --build`：双 target 0 Error / 0 Warning；`check_menu_table` 通过
2. 静态检查：`check_chars`（`!` 编入后 orphan 变化）、`fix_bom`（`menu_table.h` 是新文件，含中文注释就要 BOM）
3. 逻辑对拍（可复用 `build_tools/algo_audit.py` 的做法）：把"可见数 / 压缩下标 / RawAt / 跳过隐藏项"移植成 Python，穷举 `count 1..8 × 隐藏位置 × 移动方向 × 起点`，验证：
   - 可见项遍历顺序与"把隐藏项从列表里删掉"完全一致
   - 环绕行为一致（首↔末）
   - 全隐藏时 `vis == 0` 且不进入死循环
4. 真机：上电 → 顶层列表 5 项、无温度校准；进版本页长按 → 出现 `!`；退出 → 顶层 6 项、温度校准在 PID设置 与 手柄型号 之间；旋钮上下转不经过"空白格"；断电重启 → 恢复 5 项
